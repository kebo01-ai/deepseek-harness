# @deepseek-ai/dsh-experimental-client-ui-cc-board

[English](README.md) | 中文

## 概述

往 Web 客户端加一个顶级侧栏入口，点进去是一整页卡片，workbench 板子所报告的每个外部 agent 会话一张。每张卡片带着那个会话的活动状态词、板子从哪里够到它、捕获到的屏幕，以及一个往里打字的框。页面自己持有轮询驱动：离开它、把它那个标签页藏起来、或者把它暂停，都会停掉每一次读取。读与写都走 Host 侧那个 cc-session 服务，所以浏览器里不存任何板子凭据，也不存任何会话状态。

<a id="use-this-package"></a>
## 使用本包

在稳定版 Web 包与 Host 侧的 [`@deepseek-ai/dsh-experimental-cc-sessions`](../cc-sessions/README.zh.md) 服务之后安装本包，板子端点与口令配在那一侧。Web Client 加载器挂载 `/client` 导出；根 Host 导出是惰性的，本包没有任何用户配置字段。

### 打开看板

那一行侧栏行坐在全局面板里，id 是 `cc-sessions`，这也是它打开的那块主面板的键 —— 侧栏是按被点那一行的 id 去寻址它打开的页面，所以这两样刻意是同一个字符串。打开它会立刻读一次板子，而不是干等第一个间隔走完，然后按 Host 服出来的节奏接着读。从没够到自己那个 Host 的页面，是一个节奏都没被服到的页面，它会按自己那个短间隔重试到有一个回答落地为止，而不是停下来。页头说明它读的那个板子 URL、这次回答带了多少会话与多少节点、Host 向板子要的是哪一种扫法、这次读取是多久以前落下的、以及轮询是不是暂停了。

### 读一个会话

卡片把板子自己的活动状态词摆在一个点旁边。屏幕读取恰好覆盖这个页面正在显示的那些会话，一次一批，而一张卡片永远说明自己手里是三种回答里的哪一种：还没读到过一屏、板子捕获到的是一块空屏、或者这次读取失败了而板子自己给的原因就站在屏幕本该在的位置上。在成功过一次之后才失败的读取，会留着它上次拿到的那一屏、把原因说在它旁边，因为读者两样都要：停住不动的那张画面，以及它为什么停住。

### 往一个会话里打字

Enter 提交这一行并清空那个框；Shift+Enter 开新行，而一次 IME 合成提交不算提交。板子没收下的那一行留在框里给读者重试，原因就在它发生的那张卡片上 —— 板子的拒绝与一次失败的写入分开说。板子不让写的那一行，它的撰写框是关着的、并说明板子自己给的阻挡原因；板子进程它本身那一行也一样。

### 失败是什么样

第一个回答落地之前，页面说它正在读板子。传输失败说明 Host 给的错误码与消息。Host 读得到、但自己报了麻烦的板子，会把那个原因留在它确实读到的那个列表旁边，而不是把页面清空。一个被记住的回答会说自己是被记住的、以及它有多旧，扫不到的节点会被点名，而回答了「没有会话」的板子会说自己是空的 —— 读不动的板子永不这么说，因为读者这时要的是那句说明过的原因。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内幕 —— 点击展开</summary>

Client 导出挂载来自 [`@deepseek-ai/dsh-experimental-cc-sessions/remote`](../cc-sessions/README.zh.md) 的生成式 `ctx.remote.ccSessions` 贡献，然后通过 Cordis effect 注册它的语言词典、一行侧栏行与一块主面板。在挂载之后才失败的注册会先把 Remote 命名空间卸掉再把错误抛出去；处置插件 fiber 会把它们全部移除。

交给页面的那三个动作就是这道缝的全部。`loadRoster` 把 Host 说明过的原因留在它回答的那个视图旁边，所以读不动的板子是一句话、不是一片空白。`loadPane` 回答的是捕获到的文本加上一条「它为什么不在」的原因，这把「这次读取拿不到的屏幕」与「真的是空的屏幕」分开 —— 让一个空字符串同时代表这两样，正是让一张卡片悄悄变白的那个原因。`send` 把 `refused` 与 `failed` 分开，因为一块拒绝了写入的板子不等于一块写不进去的板子。传输失败渲染成它的错误码与消息，而这两样永不带板子口令。

### 驱动

两个 ticker 都由 effect 启动、并在卸载时清掉。`running = !paused && !hidden` 是唯一那道闸：被藏起来的标签页算作已离开，因为板子是一个共享服务，而没人看着的页面不该继续扫它。名册 ticker 不等第一个回答就起步，因为一个只有读到了板子才开始轮询的页面，永远没法从「读不到板子」里恢复。每次读取用一个忙标志挡住重入，所以慢板子是把下一次读取推后，而不是把读取堆起来；这个标志无论读取怎么结束都会被放开，而抛出来的读取像任何别的失败一样被说明，因为一个留在置位上的标志会把页面锁死到它被关掉为止。屏幕 ticker 按「谁在板子上」取键，而不是按名册数组的身份 —— 每次读取都递回一个新数组 —— 所以成员变了它重启、只有状态动了它接着走。每一批屏幕读取都用它自己那批回答把整份记录重建一遍，所以板子不再报告的会话会连着它那一屏一起离开。在卸载之后才落地的读取什么都不发布。

| 文件 | 角色 |
|---|---|
| [`src/client/mount.ts`](src/client/mount.ts) | 生成式 Remote、语言、那三个动作、以及两处槽位注册 |
| [`src/client/CcBoardPanel.tsx`](src/client/CcBoardPanel.tsx) | 页面、那些板子事实、以及轮询驱动 |
| [`src/client/CcSessionCard.tsx`](src/client/CcSessionCard.tsx) | 一个会话：点的映射、那三种屏幕状态、撰写框、以及按卡片记的失败 |
| [`src/client/face.ts`](src/client/face.ts) | 动作面、结果类型、以及那个按会话的键 |
| [`src/client/locales.ts`](src/client/locales.ts) | 中英两套页面文案 |
| [`src/index.ts`](src/index.ts) | 惰性的 Host 入口 |

一个会话跨多次读取按 `targetKey` 追踪 —— 节点与名字一起，因为板子就是这么寻址一个会话的，而名字会在不同节点上重复。`dotOf` 只给板子已知会发出的那两个词上色；其它一律停在 warning，而不是被猜成一个健康的颜色，而那个词本身原样抵达读者、就摆在点的旁边。

</details>

<a id="model-experience"></a>
## 模型体验

没有，因为这个浏览器投影不注册任何面向模型的输入。页面上那些会话属于板子，读者在这里打的任何东西都到不了一次 dsh 模型请求。

#### KV Cache 影响

无直接影响。本包产出的任何东西都到不了一次模型请求里。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **只有读与打字** —— Host 那道缝没有任何生命周期动词，所以页面无法启动、停止或杀掉一个板子会话。那仍归板子，而一个能结束它自己看不见的工作的页面，对这件事来说就是错的那个面。
- **一块屏幕，不是一个终端** —— 卡片渲染的是捕获到的文本，所以板子会话的光标、颜色与备用屏都不会被复现。要交互式地读一个会话，仍归板子自己的终端。
- **页面遵守服出来的节奏** —— `rosterIntervalMs` 与 `paneIntervalMs` 来自 Host，在页面上调不了；暂停与一次手动刷新就是全部的控制集。页面在「一个节奏都没被服到」的时候用的那条重试，是写在页面里的一个固定间隔，因为那种情形是一个够不到自己 Host 的浏览器，它的重试根本到不了那块共享板子。
- **每一批都读遍显示中的每个会话** —— 这里没有视口收窄也没有选中收窄，所以一块会话很多的板子每一跳要花掉「每个会话一次屏幕读取」。板子大到让这件事开始要紧时，它要的是先有一个选中。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>给维护者的工作上下文 —— 点击展开</summary>

板子的终端与它自己的页面都不是本包该改的，板子的词汇也一样：活动状态词、写入阻挡原因、以及一次拒绝，都以板子说出来的样子抵达读者。要扩这个页面的时候，先加一个投影或一句说明过的原因，再去向 Host 要一个新动词。

驱动的存活期是行为，不是注释：暂停、标签页被藏、以及已处置这三种情形各有自己的测试，断言读取计数不再动。任何把轮询搬出这个组件的改动，都得把这三条论断一起带走。

</details>

**运行期不变式：** 不发布 companion。RPC 是权威，而本包只拥有几处可处置的槽位注册。
